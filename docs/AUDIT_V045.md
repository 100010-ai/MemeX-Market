# MXM v0.45 — аудит проекта

Дата статического аудита: 19.08.2026.

## Область проверки

Проверены публичные API маршруты, Telegram-аутентификация и сессии, Supabase RPC/RLS границы, торговля мемкоинами, рынок Telegram Gifts, корзина и офферы, rewarded-реклама, админские действия, загрузка внешнего медиа, idempotency/locking, конфигурация окружения, release-gate, TypeScript и ESLint.

Это статический аудит исходников. Он не заменяет нагрузочное тестирование, DAST против production URL и аудит фактических Supabase policies после применения всех миграций.

## Исправлено в v0.45

### HIGH — рекламную награду можно было подделать на клиенте

Ранний вариант rewarded ads позволял браузеру завершить локальный таймер/SDK-flow и вызвать начисление без независимого подтверждения рекламной сети. Модифицированный клиент мог превратить это в бесконечный faucet.

Исправление:
- в production начисление выполняется только после server Reward URL callback;
- callback защищён отдельным server-only secret и timing-safe сравнением;
- один пользователь не может иметь несколько открытых rewarded-сессий;
- начисление выполняется атомарно и повторный callback идемпотентен;
- client fallback теперь физически отключён в `NODE_ENV=production`, даже если переменная окружения ошибочно включена;
- AdsGram Block ID валидируется, server secret должен быть не короче 32 символов.

### MEDIUM — PnL считал награды и административные начисления прибылью

Профиль раньше мог показывать PnL как разницу между net worth и стартовыми 100 TON. Из-за этого реклама, задания, ручные начисления и комиссия запуска мемкоина выглядели как торговая прибыль/убыток.

Исправление: PnL берётся из `realized_pnl` фактических сделок.

### MEDIUM — частичный успех при создании мемкоина

После успешного атомарного RPC код дополнительно менял статус/видимость монеты. Если второй запрос падал, пользователь уже платил комиссию, но API мог вернуть ошибку и интерфейс предлагал повторить операцию.

Исправление: весь запуск заканчивается в одном RPC; после успешного RPC нет дополнительной обязательной мутации.

### MEDIUM — рассинхрон версии экономики при rolling deploy

Новый frontend мог показать комиссию 150 TON, пока база ещё содержала старую функцию с другой комиссией.

Исправление: `/api/coins` проверяет `economy_settings.schema_version >= 45`; до применения миграции запуск блокируется до списания средств.

### MEDIUM — Telegram media/TGS без достаточных лимитов

Скачивание внешнего Telegram-файла могло занимать слишком долго или распаковать чрезмерно большой TGS/Lottie payload.

Исправление:
- timeout Telegram file fetch;
- лимит исходного файла;
- лимит compressed TGS;
- `maxOutputLength` для gzip;
- лимит распакованного JSON;
- проверка структуры JSON;
- публичные media endpoints больше не обязаны отдавать пользователю сырую ошибку провайдера.

### MEDIUM — настройки экономики могли разойтись

Комиссия Gifts хранилась в market settings, а остальная экономика — отдельно. Две последовательные admin-мутации могли завершиться наполовину.

Исправление: `update_economy_settings_v045` меняет параметры экономики и комиссию рынка в одной транзакции.

### MEDIUM — комиссии AMM не попадали в экономический аудит

0,5% комиссии мемкоин-сделок реально уничтожались торговой математикой, но админка не видела этот sink. Из-за этого «чистое изменение экономики» было завышено.

Исправление: trigger `trades_economy_fee_v045` пишет комиссию каждой новой сделки в `economy_events` как `coin_trade_fee`; админка учитывает её в дневном изъятии.

### UI/UX — некорректный экран запуска мемкоина

Убрана вводящая в заблуждение «Стартовая позиция 25 000 000 TON». Экран теперь показывает настоящие параметры внутренней модели:
- стартовая капитализация: 100 виртуальных TON;
- AMM liquidity: 200 виртуальных TON;
- комиссия сделки: 0,5%;
- комиссия запуска: 150 виртуальных TON;
- 12 часов между запусками;
- максимум 2 активных мемкоина на создателя.

### LOW — версия `package-lock.json` отставала от релиза

`package.json` уже был `0.45.0`, а root metadata в `package-lock.json` оставалась `0.44.0`. Это не меняет runtime-зависимости, но ломает воспроизводимость release metadata и может путать CI/артефакты. Lock metadata синхронизирована с v0.45 и добавлена в release-gate.

### LOW/MEDIUM — одна повреждённая запись могла уронить всю ленту

`lib/feed.ts` раньше бросал исключение, если у исторического market event уже удалён actor или появился новый тип события, которого старая версия frontend не знает. В результате один старый/новый event мог превратить `/api/feed` в 500 для всех.

Исправление:
- удалённые actors показываются как «Удалённый игрок»/«Система»;
- неполные связанные записи пропускаются локально;
- неизвестные будущие event kinds игнорируются вместо падения всей ленты;
- limit жёстко ограничен диапазоном 1–100;
- убраны десятки `any` из feed parser.

### UI/UX — фильтры Gifts и лишняя панель рынка

Отдельные dropdown-sheet находились внутри горизонтального overflow-контейнера и могли визуально обрезаться Telegram WebView. Также справа отображался перегруженный блок со сводками коллекций/floor.

Исправление:
- один portal-based filter drawer через `document.body`;
- mobile bottom sheet / desktop side drawer;
- поиск внутри длинных фильтров;
- Apply/Reset;
- убрана публичная коллекционная sidebar-панель;
- рынок стал content-first и занимает полную ширину.

## Экономика v0.45

Базовые параметры:

| Механика | Значение | Роль |
|---|---:|---|
| Стартовый баланс | 100 TON | первоначальная ликвидность игрока |
| Rewarded ad | +50 TON | добровольный faucet |
| Лимит rewarded ads | 2/сутки | максимум +100 TON/сутки |
| Cooldown рекламы | 30 мин | защита от спама/фарминга |
| Onboarding-задания | 60 TON суммарно | пользователь может развиваться без обязательной рекламы |
| Daily-задания | ~12 TON/сутки | мягкая регулярная эмиссия |
| Launch fee | −150 TON | крупный sink против спама монетами |
| Cooldown launch | 12 ч | ограничивает поток новых монет |
| Active coins/creator | 2 | ограничивает мусорные рынки |
| AMM trade fee | 0,5% | постоянный sink на обороте |
| Gift market fee | 2,5% | уходит системному казначейству |

50 TON за рекламу — только внутренняя единица баланса MXM. Она не является on-chain TON, не выводится и не обещает денежную стоимость.

## Что осталось после аудита

### MEDIUM — масштабирование admin overview

Админский overview сейчас постранично выгружает целиком несколько таблиц, чтобы посчитать агрегаты и дать полные списки. На текущем небольшом проекте это удобно, но при десятках/сотнях тысяч строк станет дорогим по времени и памяти.

Рекомендация: вынести KPI в SQL aggregate RPC/view, а таблицы игроков/Gifts/coins загружать server-side pagination по активной вкладке.

### LOW/MEDIUM — часть публичных API всё ещё использует сообщения PostgreSQL

Некоторые business mutation routes возвращают `error.message`, чтобы пользователь видел причину вроде «недостаточно баланса». Это полезно для UX, но техническая ошибка БД при неожиданном сбое также может просочиться наружу.

Рекомендация: централизованный mapper кодов/известных business exceptions -> русские сообщения, а неизвестное только в server log.

### LOW — legacy React/ESLint warnings

ESLint не показывает ошибок, но в старых компонентах остаются предупреждения про `set-state-in-effect`, `<img>` для внешнего/динамического медиа и несколько `any` в отдельных API response-normalizers. `lib/feed.ts` в этом релизе уже переведён на явные типы. Это не release blocker, но оставшийся долг повышает стоимость будущих изменений.

### LOW — CSP пока не включён

Есть `nosniff`, `Referrer-Policy`, `Permissions-Policy`, `CORP`, выключен `X-Powered-By`. Строгий CSP не добавлялся автоматически, потому что проект использует Telegram, Supabase, AdsGram и внешнее NFT media: ошибочный CSP легко сломает Mini App. Перед включением нужен inventory всех разрешённых `script-src`, `connect-src`, `img-src`, `media-src`.

### VERIFY IN CI — dependency audit

`npm audit --omit=dev` в sandbox выполнить достоверно нельзя без доступа к `registry.npmjs.org`. Его нужно запускать в CI/локально с сетью перед production deploy.

## Проверки release-gate

`scripts/release-check.mjs` проверяет, среди прочего:
- отсутствие игр в public API/navigation;
- наличие миграций 017–020;
- отсутствие старой «25 000 000 TON» UI-модели;
- economy schema guard перед запуском монеты;
- idempotent Gift/coin purchase paths;
- production server verification AdsGram;
- отсутствие старого forgeable v0.44 rewarded RPC;
- PnL по realized trades;
- Telegram media bounds;
- атомарное изменение экономики;
- экономический ledger и AMM fee sink;
- отсутствие вероятных секретов в архиве;
- TypeScript и ESLint.
