# MemeX Market v0.64.3 — UX & Quality Pass

This release is a visual and interaction quality pass over the existing product. No new economy/schema system is introduced.

## Player UI
- Reduced explanatory copy across Cases, Battle Pass, Progression, Store, Profile, Tasks, Creator Tools and notifications.
- Kept the fixed Telegram header and strengthened GPU/backface handling for fixed navigation surfaces.
- Added removable active-filter chips to the Gift Market without changing filtering semantics.
- Unified Gift and memecoin trade panels into a quieter, denser visual treatment.
- Tightened Gift detail metrics and trade layout.
- Improved Store card density, kept purchase-state explanations, and preserved the Stars consent flow.
- Refined case roulette presentation: stronger stage/reel depth, quieter skip/reward states, same server-authoritative result.
- Refined Battle Pass track/milestones and replaced verbose XP-source blocks with compact chips.
- Reduced task-card copy while keeping progress, channel verification and claim-all behavior.
- Clamped long notification bodies and simplified settings presentation.
- Simplified Profile customization copy and kept live frame previews.
- Reduced Portfolio bulk-listing copy without changing atomic listing behavior.
- Simplified Creator dashboard locked/empty states.
- Production global errors no longer expose backend error text to users.

## Frames
- Kept continuous/asymmetric frame silhouettes from v0.64.2.
- Carbon, Chrome and Founder ornaments were refined so small avatars do not read as disconnected straight-line decoration.
- Small-size frame ornament rendering is quieter and more legible.

## Performance / mobile
- Added `content-visibility`/containment to long Store, Battle Pass and Gift card surfaces.
- Reduced heavy shadows for coarse-pointer/mobile devices.
- Added stable numeric rendering for key compact metrics.
- Preserved Telegram safe-area and fixed-header behavior.

## /control
- Shortened dense operational explanations.
- Audit payload JSON is collapsed by default behind a `details` disclosure.
- Existing confirmations, validation and duplicate-submit guards remain intact.

## Additional bug fixed
- Gift listing post-response `after()` callback now explicitly resolves `Promise<void>` instead of propagating `Promise<GiftMarketLiquidityState | void>`. This removes a strict TypeScript/Next callback signature risk without changing market handoff behavior.

## Database
No new SQL migration is required for v0.64.3. The v0.64 progression migration must already be applied.
