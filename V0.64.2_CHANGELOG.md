# MemeX Market v0.64.2 — Existing Systems Polish

This release is deliberately a polish pass over existing product systems. It does not add a new economy or a new standalone game loop.

## 1. Cases
- Server result remains authoritative; roulette is presentation only.
- Added safe skip for the reveal animation and one-tap `Open again` flow.
- Reel generation avoids obvious adjacent duplicate cards where possible.
- Existing pity counters, disclosed odds, limited stock and history remain visible in the compact layout.

## 2. Battle Pass
- Replaced the tall reward list with a compact horizontal Free/Premium track.
- Current level auto-centers once data is loaded.
- Claim-all is surfaced whenever rewards are available.
- Current/milestone/claimed states are visually distinct and Prestige remains integrated.

## 3. Store
- Every disabled/unavailable product action now explains the reason.
- Stars first-purchase consent remains a click-time flow instead of a permanently disabled CTA.
- Primary/secondary action styling no longer depends on browser-native white button rendering.

## 4. Profile frames
- Removed the old visual language of independent straight-line decorations.
- Frames use continuous conic/metal/glass rings, asymmetric silhouettes and integral ornament nodes.
- Added orbit detail rendering and retained reduced-motion handling.

## 5. Profile
- Tightened layout and expanded the useful stats grid.
- Added a compact achievement showcase linked to progression.
- Equipped cosmetics remain rendered through the shared ProfileAvatar component.

## 6. Achievements
- Added category filters and completion counters.
- Unlocked achievements sort ahead of incomplete entries.
- Cards expose progress, rarity and XP reward without oversized panels.

## 7. Daily Streak
- Kept the claim fully server-backed.
- Added compact 7-day reward presentation plus current/best/total claim context.
- Client device time is not used as the source of truth.

## 8. Collection Book
- Added search and progress/name/floor sorting.
- Trait completion remains split by Model / Backdrop / Symbol.
- Missing collections can jump directly into the existing market filter.
- Milestone claim controls are compact and state-aware.

## 9. Gift Market
- Market UI state persists in session: tab, search, filters, sort, view mode and scroll position.
- Returning from a gift restores the user's market context.
- Explicit URL filters override stored state so deep links remain deterministic.

## 10. Memecoins
- Buy/sell keeps the existing optimistic transaction + rollback behavior.
- Confirmed trades now show a concise success state and refresh authoritative data in the background.
- Busy-side switching and invalid amount states are guarded.
- Slippage and detail tab choices persist for the session.

## 11. Tasks
- Added claim-all for ready missions.
- Progress refreshes when the Mini App regains focus/visibility.
- Bulk claims use settled results and still refresh after partial failure.

## 12. Leaderboard
- Equipped profile frames now render in leaderboard rows and podium.
- The selected board persists for the session.
- A user's rank is pinned when they are outside the returned top list.

## 13. Portfolio
- Existing gifts/listed/coins views now keep the active tab for the session.
- Added useful gift and coin sorting without changing ownership semantics.
- Existing realtime/listing/bulk-sale behavior remains intact.

## 14. Notifications
- Added All/Unread filtering and guarded preference toggles.
- Mark-one/mark-all interactions keep optimistic rollback.
- Replaced browser-dependent toggle visuals with the MXM switch component.
- Existing internal deep-link validation remains intact.

## 15. Creator Tools
- Reworked the page into compact entitlement + token status sections.
- Active tools show expiry where applicable.
- Coin rows expose current boost/analytics state and direct actions.

## 16. /control
- Prevents duplicate mutation submission while another control action is active.
- Destructive/sensitive balance, XP and ban actions require confirmation.
- Balance/XP inputs reject non-finite values before sending.
- Success notices identify the completed action; server-side permissions/audit remain authoritative.

## Cross-cutting Telegram/mobile polish
- Top bar stays fixed to the viewport with safe-area compensation.
- Native checkbox/radio appearance is restored while button tap/focus behavior remains normalized.
- Compact page spacing and coarse-pointer behavior are preserved.

## Database
v0.64.2 itself adds no schema migration. It expects the already-shipped v0.64 progression migration (`100001_progression_update_v064.sql`) to be applied.
